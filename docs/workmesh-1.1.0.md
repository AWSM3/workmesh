# Требования Workmesh 1.1.0

Цель версии — дать пользователю возможность менять персоны и правила проекта через диалог, прослеживать их применение в каждом узле и восстанавливать историю закрытой работы. Настройки и трейсы относятся к выбранному корню проекта.

## 1. Управление персонами

По запросу пользователя агент читает `.workmesh/personas/` и действующую конфигурацию, затем предлагает добавить или уточнить нужные персоны. Для каждой указывает ответственность, входы, ожидаемый результат и критерии приёмки. Перед записью показывает изменения, включая привязки в `workflow.yaml` и проверки в `quality.yaml`, если они затронуты. Существующие персоны переиспользуются, когда подходят по назначению.

На запрос о фронтендере, бэкендере, разработчике БД и ручном UI-тестировщике агент может настроить четыре проектные персоны. В прогоне Splitter выбирает те из них, которым есть работа по текущей задаче.

## 2. Управление правилами и передача в узлы

Агент раскладывает предложенные правила по подходящим категориям из `.workmesh/rules.md`. Например, переиспользование shared-компонентов относится к фронтенду, описание источников и преобразований данных и миграции Liquibase — к данным, а DRY, KISS и SOLID — к общим правилам разработки. Агент показывает формулировки и области применения. После согласования обновляет канонические файлы `rules/r-<категория>.md` и корректирует индекс, когда меняются категории, их области или ссылки.

Splitter выбирает общие и предметные правила отдельно для каждого узла. Бриф каждого делегированного исполнителя содержит ID и точные формулировки применимых правил. Свежий Critic получает тот же набор для проверяемого результата и по каждому обязательному правилу возвращает статус и основание. Quality Gate аналогично проверяет правила для собранного результата. Способ делегации может меняться от клиента к клиенту, состав брифа сохраняется.

## 3. Наблюдения и предложения Learning Agent

По ходу работы исполнители и ревьюеры фиксируют воспроизводимые удачные приёмы и повторяющиеся ошибки с конкретным примером или ссылкой. Learning Agent сопоставляет наблюдения с действующими правилами и предлагает новое правило либо изменение существующего. В предложении указывает, что произошло, какую пользу даст изменение, где оно применимо и когда требуется исключение. При корректировке существующего правила показывает старую и новую формулировки.

Пользователь отдельно подтверждает изменение правила. До решения предложение сохраняется с прогоном. Согласованное правило вступает в силу для следующих подходящих прогонов.

## 4. Трейсы и закрытие работы

Workmesh создаёт `.workmesh/trace/<задача>-<id>/` для каждого прогона. `run.md` содержит цель, граф, состояние и ссылки. Брифы, результаты и проверки лежат по узлам и попыткам. При возобновлении используется тот же каталог. Ссылки на итоговые артефакты указывают на их рабочие пути и проверенные версии.

- После Quality Gate агент передаёт конкретную версию на утверждение. При отсутствии решения завершает выдачу прямым вопросом «Утверждаешь завершение работы по этой версии?» и сохраняет состояние ожидания.
- Однозначное распоряжение завершить работу с этой версией, например закоммитить и запушить проверенный результат, считается утверждением. Если распоряжение включает финальное действие, Workmesh записывает решение, выполняет действие и проверяет его результат перед закрытием.
- При замечаниях, паузе, блокере или незавершённом финальном действии Workmesh сохраняет рабочие материалы для продолжения. При явном закрытии незавершённой или отменённой задачи фиксирует фактический статус и оставшуюся работу.
- При закрытии Workmesh формирует короткий `summary.md` и при необходимости приложения. В них остаются итог, версия и решение пользователя, существенные решения и доработки, проверки, ссылки на реализацию и статус предложений Learning Agent. Перед очисткой рабочих записей агент проверяет ссылки и сохраняет свидетельства, нужные для восстановления истории.

## Сквозная приёмка

В проекте с четырьмя персонами пользователь добавляет три категории правил и просит вывести данные нового источника на экран. Проверка показывает, какие персоны назначены, какие правила попали в брифы нативных субагентов или отдельных сессий и чем независимый ревьюер подтвердил соблюдение правил. Learning Agent предлагает обоснованное улучшение. При выдаче результата Workmesh явно запрашивает решение пользователя. Ответ «закоммить и запушь» закрывает прогон после проверки публикации. В новом чате по `summary.md` можно найти принятую реализацию и восстановить причины существенных решений. При провале публикации из рабочего трейса можно возобновить финальное действие.
