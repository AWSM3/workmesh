# Workmesh

Workmesh — «сеть совместной работы». Задачи, исполнители и проверки связаны графом. Веди прогон в рамках действующих инструкций и полномочий проекта.

Если бриф помечен как внутреннее поручение Workmesh и содержит ID прогона, узел и роль, выполни только этот узел в указанном прогоне и верни результат координатору.

## Выбери сценарий

- **Подключение или перенастройка.** Пройди [чек-лист подключения](references/project.md#чек-лист-подключения). Для существующего проекта сверь действующие инструкции и настройки. В чистой папке предложи исходный `AGENTS.md`. При подключении прямо спроси, должен ли Workmesh вести каждую последующую задачу пользователя в выбранной области. Получи явное «да» или «нет». Покажи граф и diff, затем примени согласованные изменения и проверь, какие инструкции загружает клиент.
- **Прогон или предпросмотр графа.** Определи корень проекта и прочитай применимые `.workmesh/workflow.yaml`, `quality.yaml`, персоны и профиль. Из `rules.md` выбери только подходящие категории. Сверь доступные инструменты с [картой клиентов](references/harnesses.md). Предпросмотр заканчивается графом, критериями и выбором исполнителей.
- **Утверждение версии или правила.** Найди соответствующую версию прогона или кандидата. Перед изменением статуса сверяй, к чему относится решение пользователя.

## Спроси в ведущей сессии

Используй первый поддерживаемый вариант для текущего клиента. Проверь доступность и разрешение на вызов. Собирай открытые вопросы небольшими группами с возможностью свободного ответа.

| Клиент | Ask по умолчанию |
| --- | --- |
| Codex | `request_user_input_async` там, где он предоставлен. Иначе доступный `request_user_input` в поддерживаемом режиме. |
| OpenCode | `question` при поддержке текущим интерфейсом. |
| Hermes Agent | `clarify` при наличии в инструментах ведущей сессии. |
| Pi | Зарегистрированный инструмент `question` либо настроенный аналог. Форма доступна через расширение. |
| Claude Code | `AskUserQuestion` в ведущей сессии при доступном разрешении. |

Если подходящей формы нет, задай вопросы прямо в чате. Дождись ответа, когда без него нельзя выбрать область настройки или получить обязательное решение. Для фонового запуска сохрани запрос и состояние ожидания.

При обязательном режиме из инструкций проекта запускай Workmesh для каждой новой задачи пользователя в указанной области. Для небольшой задачи достаточно графа с одним рабочим узлом. Внутренние поручения воркерам, шаги текущего прогона и само подключение веди в рамках уже выбранного сценария.

## Построй и исполни граф

1. **Splitter** фиксирует ожидаемый итог, ограничения, критерии и зависимости. Для каждого узла назначает персону, задаёт входы и их версии, ответственность, формат результата и свидетельства. При параллельном редактировании назначает каждому исполнителю свой участок или согласованный способ сборки.
2. **Ведущий агент** использует нативную делегацию. Если она недоступна или не даёт нужной изоляции, запускает отдельную именованную сессию через поддерживаемый и разрешённый путь. Записывает логическое имя `workmesh/<run-id>/<node-id>/<role>-a<attempt>`, например `workmesh/venues-04/offer-b/critic-a2`, реальный ID клиента, версию задания и путь выдачи. Имена адаптирует к правилам клиента. Начинай каждый дочерний бриф, включая ручную передачу, с отметки «Внутреннее поручение Workmesh», ID прогона, узлом и ролью. Независимые готовые узлы можно запускать параллельно в пределах проектного и клиентского лимитов.
3. **Worker** возвращает версионированный артефакт, доказательства проверок и открытые вопросы. Его предварительная самопроверка помогает подготовить передачу результата. **Critic** проводит независимую проверку ветки по её критериям. Для подтверждённого дефекта ведущий агент передаёт исполнителю точное замечание и запускает новый цикл на следующей версии в пределах лимита.
4. **Merge** принимает проверенные версии и собирает итог. Для общего **Quality Gate** выдели свежего ревьюера. Возвращай дефект части её владельцу, дефект сборки — Merger, пробел в плане — Splitter. При изменении входа перепроверяй затронутые зависимости. Каждую обновлённую сборку проверяй перед передачей на утверждение.
5. **Human Approval** показывает человеку версию, краткий итог проверок и существенные отклонения. Запиши решение по этой версии. Утверждение закрывает прогон, замечания открывают адресную доработку, отсутствие ответа оставляет ожидание. При исчерпании лимита покажи блокер и принятые части.

У отдельной сессии должны быть разрешённый источник входов и рабочий канал возврата результата. Сверь запись возврата с назначением. В ней нужны ID прогона, узла и сессии, роль, номер попытки, версия задания или входов, версия и ссылка на выданный или проверенный артефакт, статус и свидетельства. При недоступности подходящего пути зафиксируй блокер и передай человеку компактное задание для отдельной сессии. Возобнови ветку после получения результата с подтверждаемым происхождением.

## Настрой независимое ревью

Для каждого Critic, предметного Reviewer и Quality Gate начни свежий контекст независимо от автора и предыдущих проверок этой версии. Сначала используй нативного чистого субагента, затем отдельную новую сессию. Передай [базовую персону Reviewer](assets/personas/reviewer.md) и применимую специализацию [Critic](assets/personas/critic.md) или [Quality Gate](assets/personas/quality-gate.md). Добавь проектные критерии, требуемый артефакт, его версию, исходные требования и проверяемые свидетельства. История исполнителя, его самооценка и ожидаемый вердикт остаются вне пакета ревью.

Ведущий агент собирает выводы по критериям и сверяет места, источники и свидетельства. Если свежая независимая проверка недоступна, сохрани статус обязательной проверки как заблокированный. Новую версию передай новому ревьюеру.

## Примени уроки к следующим прогонам

Learning Agent предлагает правило с условием, действием, областью и ссылкой на подтверждаемый эпизод. До согласия пользователя кандидат хранится с прогоном. После согласия обнови категорию в `.workmesh/rules/r-<slug>.md` и при необходимости её строку в индексе `.workmesh/rules.md`. Сверь ссылку, область и возможный конфликт с действующими правилами. Splitter применяет только подходящие активные записи.
